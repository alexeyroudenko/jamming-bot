# 2026-04-27–2026-04-28 — что изменилось в репозитории

Краткий разбор коммитов за **2026-04-27** и **2026-04-28** (источник: `git log` по дате коммита).

## 2026-04-27

### Инфраструктура и деплой

- **GeoIP**: переход с dbip-city-lite на **GeoLite2-City** (`deployment.yaml`, Dockerfile с ключом лицензии, `MMDB_PATH` в `ip.py`); из ingress убран неиспользуемый путь semantic-сервиса.
- **Coroot CE**: цели Makefile `k3s-coroot` / `k3s-coroot-uninstall`, `coroot-values.yaml`, дополнения в `DEPLOY.md`, первый вариант `coroot-runbook.md`.

### Flask и bot-service

- По умолчанию включены **`do_analyze`, `do_storage`, `do_geo`, `do_screenshot`**.
- Модуль **`storage_http`**: потокобезопасные HTTP-запросы к storage, рефакторинг post/patch; в deployment подняты **CPU** для нагрузки.
- **Индексы и выбор URL** в таблице Urls (hostname, статус визита): быстрее выбор непосещённых ссылок, проверки и счётчики по hostname, кэширование, аккуратнее логи при ошибках создания индексов.

### Наблюдаемость и UI

- **OpenTelemetry** в bot-service: переменные `OTEL_*`, экспорт в Jaeger, spans на HTTP и операции с БД.
- **Dashboard**: маршрут **`/events`**, стили, навигация, socket-клиент для событий в реальном времени.

## 2026-04-28

### OpenTelemetry Collector и Coroot

- Развернут **`otel-collector`** в манифесте `deployment.yaml` (сервис под OTLP), приложения шлют трейсы на `http://otel-collector:4318` вместо прямого Jaeger.
- Конфигурация под интеграцию с Coroot: секреты/переменные окружения, описание в `DEPLOY.md` и в `coroot-runbook.md` в корне репозитория.
- Доработки конфигура коллектора: опциональный API-ключ и заголовок (пустое значение по умолчанию), отключение gzip-декомпрессии там, где это нужно для Coroot.

### steps-service

- Облегчён фоновый рефреш: предпочтение **latest JSON с лимитом** вместо полного CSV; прокси лимита через app-service; по умолчанию подтягивается только нужный PNG, остальное по запросу.
- Эндпоинты **`GET /live`** и **`GET /ready`** для проб Kubernetes; смягчены тайминги проб; подняты **CPU requests/limits**.
- Исправление зависания readiness при **обрезанном или пустом JSON**: fallback, меньший лимит для latest, таймаут парсинга JSON **90 с**.
